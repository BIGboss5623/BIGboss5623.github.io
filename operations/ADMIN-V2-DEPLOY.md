# ZGLAND 管理中心 V2 上线说明

此分支不包含任何管理员密码、实际密钥或私人数据。当前生产 main 仍保留 V1，待配置和测试完成后再合并，避免未配置认证导致管理员无法进入。

## 1. Cloudflare 生产环境配置
1. 在 Cloudflare 控制台 → Workers & Pages → D1 创建独立数据库，例如 zgland-admin。
2. 打开数据库 SQL 控制台，执行 operations/admin-schema.sql。此版本针对尚未配置的新数据库；若已执行旧版 schema，须先核对列结构，再添加 ip_address、country、region、city 四个 TEXT NOT NULL DEFAULT '' 字段，避免重复 ALTER。
3. 在现有 zgland.com 对应 Pages 项目 → Settings → Bindings 添加 D1 数据库绑定，名称 ADMIN_DB，选择上述数据库。
4. 在 Settings → Variables and Secrets 的 Production 环境添加加密 Secret：
   - ADMIN_PASSWORD：站主选定的密码，直接在 Cloudflare 控制台输入，不填入 Git、脚本或聊天记录。
   - ADMIN_IP_KEY：独立高强度随机字符串（至少32字符，建议64位十六进制随机数），用于 IP 摘要及会话保护。不要复用任何现有 API token。
5. 确认绑定/密钥完成再合并此分支到 main，并等待现有 Pages 部署完成；生产域名验证必须通过。预览域名的管理路由重定向生产域名，不用于验证真实账号。

## 2. 行为
- 同一 Cloudflare 客户端 IP 连续20次密码错误，限制管理中心访问30分钟；正常登录清零；限制期间不继续计数或延长，正确密码也不放行。
- 不影响主站、资料库或其他独立业务。共享出口 IP 可能同时限制同网段的其他管理用户。
- 7天绝对会话有效期（仅建议可信设备，清除 Cookie 或换设备可能提前失效），安全 HttpOnly / Secure / SameSite=Strict cookie；退出撤销服务端会话；更换密码或 IP_KEY 后既有会话不再有效。
- D1 记录最近登录、失败、限制和退出事件；后台仅向已登录管理员展示时间、事件、完整客户端 IP、Cloudflare 提供的国家/地区/城市，缺失显示未知，不调用第三方定位接口。IP 地理位置是估算而非真实住址，VPN/代理可能导致偏差。查询最近365天内的最新100条；成功登录时清理超过365天的审计记录、过期会话及超过30天的失效尝试记录。不得公开导出登录记录。
- 认证缺失、数据库异常、来源信息缺失时关闭管理入口，不降级为无密码后台。
- 量化服务与统计健康状态按固定公开接口检查，不允许自定义URL或执行远程命令。
- 既有 Cloudflare、GitHub、域名、量化、资料库管理仍使用各服务原有认证。

## 3. 验收
先在隔离测试环境以虚构密码和 IP 验证 19/20 次、IP 隔离、暂停到期、成功清零、退出与过期、跨站 POST 拒绝及数据库异常。额外核对第6天仍有效、第7天失效、IP与地理位置仅管理员可读。正式发布后只做一次正常登录和退出，不在正式站点制造20次错误。核对未登录访问 /admin/ 会跳到登录，/admin/api/audit 返回401，且主站保持可访问。

## 4. 恢复
若发布异常，通过 GitHub 正常回退本分支相关提交；禁止强制推送或删除既有网站历史。密码泄露时在 Cloudflare 轮换 Secret 后重新部署，旧会话失效。数据库含审计记录及会话摘要，仅保存在 Cloudflare D1。代码仓库公开，不能把静态文件当成私人资料存储；真正的审计与私有数据仅由认证后的服务端接口返回。
