01 / PLAN

先决定模型，再决定硬件。

“脑子”是模型；“手”通常是一套工具，不必另装一个大模型。本指南采用已有权重做推理，不包含训练。以下是单用户、一次一个任务、约 4K～8K 上下文的初步预算。

R1 常见 4 位量化模型 · 文件大小来自 Ollama，其余为部署估算
模型模型文件建议整机内存预留 SSD用途
1.5B1.1GB8GB20～30GB流程实验
7B / 8B4.7 / 5.2GB16GB40～60GB简单任务入门
14B · 起步建议9GB32GB80～100GB日常分析与小项目
32B20GB48～64GB100～150GB较复杂的代码与分析
70B43GB96～128GB150～250GB更大的个人工作站
完整 R1 671B约 404GB512～768GB1～2TB服务器级初步预算

依据：Ollama 标签与文件大小 ↗ · DeepSeek 官方模型说明 ↗。小模型是蒸馏版本；量化也会改变精度。671B 一行仅是容量估算，不能据此保证可用速度。

慢一点能省显卡，不能补回模型能力。

CPU 可以推理，速度取决于 CPU、内存带宽、上下文和输出长度。磁盘空间不能等价替代运行内存；大量使用交换文件会非常慢。代码是否完整、正确，还要通过实际运行和测试确认。

32GB：优先试 14B，预留约 100GB SSD；关闭大型软件，先用 4K 上下文。

显卡、工具和“双模型”怎么加预算？

全 GPU 加速时，模型权重、上下文缓存和运行开销都要放得下。4 位量化的 8B / 14B / 32B 可分别按约 8GB / 12～16GB / 24～32GB 显存初选，仍需按实际上下文验证。显存不足可尝试部分卸载到 CPU，速度会下降。兼容性先查 Ollama GPU 文档。

普通执行工具可额外预算 2～6GB 内存、5～20GB 磁盘；浏览器、多项目依赖和容器会更多。表中整机预算已留基本工具余量。14B 思考＋8B 编程的权重合计约 14.2GB，轮流加载可先试 32GB 内存，同时常驻宜 48GB；32B＋8B 可按 64GB 内存、150～200GB 可用 SSD 预算。

02 / PREPARE

部署前，把这几项准备好。

  1. 确认系统与硬件。优先使用仍受支持的 Windows 11；Ollama 文档列出的 Windows 最低版本为 Windows 10 22H2。系统最低要求与系统是否仍获安全更新是两件事。记录 CPU、内存、显存和模型盘剩余空间。
  2. 准备独立目录。例如 D:\LocalAI\models 放权重，D:\LocalAI\workspace 放测试项目；以下路径均为示例，可换成有空间的磁盘。
  3. 安装来源选官方。准备 Ollama、Git、Python 3.12。模型初次下载、工具安装和更新需要联网；下载完成后，本地推理不需要云端模型 API。
  4. 先做一个小实验。先验证一轮问答和一个小项目，再升级大模型。编程工具先操作项目副本，保留 Git 记录。

在本机普通 PowerShell 查看信息：

Get-CimInstance Win32_Processor | Select-Object Name
Get-CimInstance Win32_ComputerSystem | Select-Object @{N='RAM_GB';E={[math]::Round($_.TotalPhysicalMemory / 1GB)}}
Get-Volume | Where-Object DriveLetter | Select-Object DriveLetter, @{N='Free_GB';E={[math]::Round($_.SizeRemaining / 1GB)}}
# NVIDIA 显卡可另运行：nvidia-smi

系统与安装路径依据：Ollama Windows 文档。

03 / BRAIN

用 Ollama 跑通本地 DeepSeek。

① 安装程序，先把模型目录设到空闲盘

从 Ollama Windows 官网下载安装包。安装后退出托盘中的 Ollama，在普通 PowerShell 执行：

New-Item -ItemType Directory -Force -Path 'D:\LocalAI\models' | Out-Null
[Environment]::SetEnvironmentVariable('OLLAMA_MODELS', 'D:\LocalAI\models', 'User')
[Environment]::SetEnvironmentVariable('OLLAMA_HOST', '127.0.0.1:11434', 'User')
[Environment]::SetEnvironmentVariable('OLLAMA_CONTEXT_LENGTH', '4096', 'User')
[Environment]::SetEnvironmentVariable('OLLAMA_NUM_PARALLEL', '1', 'User')
[Environment]::SetEnvironmentVariable('OLLAMA_MAX_LOADED_MODELS', '1', 'User')

随后从开始菜单重新启动 Ollama，并打开新的终端。环境变量不会自动改变已经运行的进程。更改模型目录不会自动搬走以前下载的权重；全新安装时先设好目录最省事。

② 下载一个明确大小的模型

32GB 内存先用 14B；16GB 改成 deepseek-r1:8b。只下载你当前要用的一档，避免一次存多份权重。

ollama --version
ollama pull deepseek-r1:14b
ollama run deepseek-r1:14b

看到交互提示后，输入“请用 Python 写一个统计 CSV 行数的小程序，给出完整代码和运行方法”。退出对话用 /bye。程序能生成回答，还不代表代码已验证。

③ 检查实际加载与本地接口

ollama list
ollama ps
Invoke-RestMethod 'http://127.0.0.1:11434/api/tags'
Get-NetTCPConnection -State Listen -LocalPort 11434

ollama ps 的 PROCESSOR 列显示 CPU / GPU 分配；接口应返回本地模型列表，监听地址应为 127.0.0.1。若服务已自动启动，不要再开一个 ollama serve；只有后台未运行时才需要手动启动。

可选：做一次有输出上限的 API 验证 
$aiRequest = @{
  model = 'deepseek-r1:14b'
  prompt = '用一句话介绍你能做什么。'
  stream = $false
  options = @{ num_ctx = 4096; num_predict = 512 }
} | ConvertTo-Json -Depth 4
$aiResponse = Invoke-RestMethod -Uri 'http://127.0.0.1:11434/api/generate' -Method Post -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($aiRequest))
$aiResponse.response

推理模型的思考也可能耗尽输出预算，必要时提高 num_predict。CPU 模式的首次加载和长推理可能等待较久。

配置与检查命令：Ollama FAQ。对话窗口也可用官方 Ollama 应用；额外的网页聊天界面不是必需项。

04 / HANDS

让模型真正修改项目。

推荐先用 Aider 作为本地编程工具：模型给出修改，工具把修改写进文件，开发工具负责运行。它不是自动控制任意桌面软件的视觉代理；浏览器点击或桌面操作还需专门工具与相应模型。

① 安装 Git、Python 与 Aider

从下方官方资源安装 Git 和 Python 3.12，重新打开普通 PowerShell：

git --version
python --version
python -m pip install aider-install
aider-install

若找不到 aider-install，重新开终端并检查 Python 的 Scripts 路径，按 官方安装说明修复；不要反复安装到不同的 Python 环境。

② 在独立测试目录接入本地模型

New-Item -ItemType Directory -Force -Path 'D:\LocalAI\workspace\hello-ai' | Out-Null
Set-Location 'D:\LocalAI\workspace\hello-ai'
git init
$env:OLLAMA_API_BASE = 'http://127.0.0.1:11434'
aider --model ollama_chat/deepseek-r1:14b --no-analytics

给它一个明确任务：“创建 app.py、README.md 和测试文件，实现命令行统计 CSV 行数；给出运行命令。”只把当前任务相关文件加入对话，先审核修改，再运行项目对应的测试。是否支持可靠的文件编辑，必须用所选模型实际验证；R1 会推理不等于每次都能正确编辑。

③ 从“代码生成”到“可用项目”

  1. 列清输入、输出、需要的文件和验收条件。
  2. 让工具修改文件；用 git diff 检查差异，确认依赖与启动说明齐全。
  3. 运行项目测试，把真实报错交回工具修改。Aider 中可用 /run 或 /test 配合具体命令，先核对命令的作用。
  4. 验收后保存 Git 提交。复杂任务拆成小步，避免让长思考挤满上下文。
“完整开源系统”与“完整训练材料”有区别。

可下载权重并使用开源工具本地运行，不代表官方公开了从零复现模型的全部训练数据与训练流水线；也不能承诺小模型达到完整 R1 或云端服务的能力。模型与工具分别核对许可证。

接入方式：Aider + Ollama · Aider 使用指南。这里明确使用本地 ollama_chat/，不要误选需要云端 API 的 deepseek 提供商。

05 / PRIVATE NETWORK

先用 ZeroTier 把两端连起来。

ZeroTier 负责让不同网络的设备互通；SSH 负责命令、文件传输和隧道；远程桌面负责画面、鼠标和键盘。三者可以配合使用。这里的“主机”是家里运行 AI 的电脑，“客户端”是你在外面使用的电脑。

  1. 打开 新版 Central 创建组织与网络，复制 16 位 Network ID。旧账户可在 Legacy Central 管理已有网络，按实际账户界面操作。
  2. 从 ZeroTier 官方下载页 给主机与客户端安装软件。托盘选择 Join New Network，加入同一个 Network ID。
  3. 在 Central 中核对两台设备的 Node ID，再授权设备。新版在设备详情中授权；旧版通常在 Members 勾选 Auth。仅输入 Network ID 并不代表已经获准访问。
  4. 记录两台设备的 Managed IP。例如主机 10.147.17.10，客户端 10.147.17.20，这些只是示例，后文必须替换为实际地址。
  5. 保留日常网络设置，不必开启全局路由、默认路由或改 DNS。按需在 Central 固定分配地址，避免后续地址变化使防火墙规则失效。

已安装后可在管理员 PowerShell 检查，若命令不在 PATH，改用托盘界面：

zerotier-cli status
zerotier-cli listnetworks
Get-NetIPAddress -AddressFamily IPv4 | Where-Object InterfaceAlias -Like '*ZeroTier*' | Select-Object InterfaceAlias, IPAddress

网络状态应为 OK 并分配地址。完成 SSH 设置后再用 Test-NetConnection 检查 22 端口；单靠 ping 失败不能判断不通，因为 ICMP 可能被防火墙拦截。受网络限制时可能经中继，速度以实际连接为准。

依据：ZeroTier 官方快速入门。已有配置入口在本站 网络连接工具，新安装优先核对官方当前版本。

06 / COMMAND LINE

用 SSH 登录主机，配置密钥。

① 主机：安装并启动 OpenSSH Server

以下修改在主机本地的管理员 PowerShell进行。先准备一个你自己的普通 Windows 账户并设置密码，日常 SSH 尽量使用普通账户；Windows Hello PIN 不是 SSH 登录密码。

Get-WindowsCapability -Online | Where-Object Name -Like 'OpenSSH.Server*'
# 如果 State 不是 Installed，再安装：
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Start-Service sshd
Set-Service -Name sshd -StartupType Automatic
Get-Service sshd

② 主机：把 SSH 入站范围限定到客户端

先在本地控制台配置，避免误操作断开现有远程会话。填写实际虚拟 IP；新增规则成功后才收紧安装器创建的宽泛默认规则。

$ztHostIp = Read-Host '主机的 ZeroTier IPv4'
$ztClientIp = Read-Host '客户端的 ZeroTier IPv4'
if ($ztHostIp -notmatch '^\d{1,3}(\.\d{1,3}){3}$' -or $ztClientIp -notmatch '^\d{1,3}(\.\d{1,3}){3}$') { throw '请填写 IPv4 地址' }
New-NetFirewallRule -Name 'LocalAI-SSH-ZeroTier' -DisplayName 'LocalAI SSH via ZeroTier' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 22 -LocalAddress $ztHostIp -RemoteAddress $ztClientIp -Profile Any -ErrorAction Stop
Get-NetFirewallRule -Name 'OpenSSH-Server-In-TCP' -ErrorAction SilentlyContinue | Disable-NetFirewallRule

如果自己以前创建过允许 22 端口或 sshd.exe 的其他规则，也要在“高级安全 Windows Defender 防火墙”核对范围；新增窄规则不会抵消别的宽泛允许规则。不需要在路由器映射公网 22、3389 或 11434。

③ 客户端：首次登录，核对主机指纹

在主机上查看指纹：

ssh-keygen -lf 'C:\ProgramData\ssh\ssh_host_ed25519_key.pub'

在客户端普通 PowerShell 操作。若缺少 ssh 客户端，在 Windows“可选功能”安装 OpenSSH Client。

$ztHostIp = Read-Host '主机的 ZeroTier IPv4'
$sshUser = Read-Host '主机上的 Windows 用户名'
Test-NetConnection -ComputerName $ztHostIp -Port 22
ssh "${sshUser}@${ztHostIp}"

显示的 ED25519 指纹与主机一致才接受。登录后可执行 whoami。Windows SSH 默认可能进入 cmd；想用 PowerShell，先输入 powershell -NoProfile。

④ 客户端生成密钥，主机安装公钥

在客户端运行，设置密钥口令；已有同名文件时不要直接覆盖：

ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\local_ai_ed25519"
Get-Content "$env:USERPROFILE\.ssh\local_ai_ed25519.pub"

复制 .pub 那一整行到主机。私钥留在客户端，不复制到主机或网站。在主机，以目标普通账户打开 PowerShell，粘贴公钥：

New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.ssh" | Out-Null
$sshPublicKey = Read-Host '粘贴客户端 .pub 的完整一行'
if ($sshPublicKey -notmatch '^ssh-ed25519\s+') { throw '请粘贴 ed25519 公钥' }
Add-Content -LiteralPath "$env:USERPROFILE\.ssh\authorized_keys" -Value $sshPublicKey -Encoding ascii

回到客户端，明确测试公钥登录：

ssh -o PreferredAuthentications=publickey -o PasswordAuthentication=no -i "$env:USERPROFILE\.ssh\local_ai_ed25519" "${sshUser}@${ztHostIp}"

输入的应是私钥口令，不是 Windows 账户密码。确认新开窗口也能登录后，再决定是否在主机 C:\ProgramData\ssh\sshd_config 设置 PasswordAuthentication no，随后管理员执行 sshd -t 验证配置、Restart-Service sshd 生效；保留本地控制台备用。

如果登录账户属于 Administrators 组

Windows 默认规则通常改读 C:\ProgramData\ssh\administrators_authorized_keys，而非用户目录的 authorized_keys；文件 ACL 需要只允许 SYSTEM 与 Administrators。不要用关闭权限检查来解决。请按 微软管理员密钥配置步骤执行；日常用独立普通账户更易分清权限。

依据：微软 OpenSSH 安装 · 微软密钥认证。

07 / REMOTE WORKSPACE

远程使用 AI，或操作整台电脑。

方式 A · SSH 命令行运行

登录主机后进入项目目录，运行 Ollama 或 Aider。程序和文件都在主机，客户端只传输命令和文本。需在该 SSH 会话重新设置 OLLAMA_API_BASE；临时断线可能终止前台任务。长任务用主机上的任务计划程序等方式托管，并保存日志，先验证退出连接后的行为。

方式 B · SSH 隧道调用主机 AI

主机上的 Ollama 保持 127.0.0.1:11434。在客户端一个新 PowerShell 窗口中填写地址并建立隧道：

$ztHostIp = Read-Host '主机的 ZeroTier IPv4'
$sshUser = Read-Host '主机上的 Windows 用户名'
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -L 127.0.0.1:11435:127.0.0.1:11434 -i "$env:USERPROFILE\.ssh\local_ai_ed25519" "${sshUser}@${ztHostIp}"

这个窗口没有输出通常是正常的，保持打开；Ctrl+C 关闭隧道。用 11435 避开客户端本身可能已占用的 11434。另开客户端 PowerShell 测试：

Invoke-RestMethod 'http://127.0.0.1:11435/api/tags'
# 如果客户端也安装了 Aider，可让它使用主机模型：
$env:OLLAMA_API_BASE = 'http://127.0.0.1:11435'
# 先进入客户端要编辑的项目目录，再运行：
aider --model ollama_chat/deepseek-r1:14b --no-analytics
模型在哪台电脑运行，与文件在哪台电脑修改，是两件事。

客户端运行 Aider＋隧道：模型在主机，文件修改在客户端。SSH 登录主机后运行 Aider：模型与文件都在主机。两端的 127.0.0.1 各自代表当前设备；公开网站不会替你启动、连接或控制这些服务。

补充 · 用 SCP 传输项目文件

在客户端项目目录中执行，沿用上面填写的用户名与主机虚拟 IP。第一条把本地 README.md 复制到主机登录账户的默认目录；第二条下载回来并另存，避免覆盖本地原件。

scp -i "$env:USERPROFILE\.ssh\local_ai_ed25519" .\README.md "${sshUser}@${ztHostIp}:README.md"
scp -i "$env:USERPROFILE\.ssh\local_ai_ed25519" "${sshUser}@${ztHostIp}:README.md" .\README-from-host.md

私钥不随项目传输；较大项目优先使用 Git 管理代码，模型权重通常无需在两端重复传输。

方式 C · ZeroTier + Windows 远程桌面

  1. 主机需要支持 RDP 被控端的 Windows 专业版、企业版、教育版或相应 Server 版本；家庭版可以作为客户端，不能直接作为微软 RDP 主机。
  2. 主机在“设置 → 系统 → 远程桌面”开启，保留网络级别身份验证，选择允许登录的账户。
  3. 在主机高级防火墙中核对 Remote Desktop 的 TCP / UDP 入站规则，把远程地址限定为客户端的实际 ZeroTier IP。不能同时留下其他面向所有地址的宽泛允许规则。
  4. 客户端运行 mstsc，计算机填写主机的 ZeroTier IP，使用主机账户登录。无需路由器公网端口映射。
  5. 家庭版可用 SSH 完成命令行工作；若确需画面，可另行评估 RustDesk 等工具的安装、密码与中继方式。

依据：微软远程桌面说明。RDP 会话下 GPU 的可用性需实测，用 ollama ps 检查；ZeroTier 不会自动唤醒一台已关机的电脑。

08 / OPERATE

遇到问题，按层检查。

模型很慢、内存不足，或电脑开始频繁读盘

先看任务管理器与 ollama ps，关闭其他大型程序，改用 8B、4K 上下文、单任务。用 ollama stop deepseek-r1:14b 卸载当前模型；要删除磁盘权重则用 ollama rm deepseek-r1:14b，以后使用需重新下载。不要把大交换文件当成等价扩容。

Ollama 11434 连不上，或提示端口已占用

先在主机执行 Invoke-RestMethod http://127.0.0.1:11434/api/tags。核对托盘进程与监听端口，已经启动时不要重复 serve。修改环境变量后需彻底退出并重新启动。Windows 原生 Ollama 与 WSL 中的服务是不同运行环境，先固定使用一个。

ZeroTier 已授权，但 SSH 超时

核对双方 Network ID、状态与 Managed IP，主机 sshd 是否 Running，再从客户端测试 TCP 22。检查主机防火墙、ZeroTier flow rules 和客户端当前 IP 是否与允许规则一致。网络显示在线不等于某个应用端口一定可达。

SSH 拒绝密钥，或 RDP 无法登录

区分账户密码、Windows Hello PIN 和私钥口令。核对用户名、普通 / 管理员公钥路径、文件权限，以及主机指纹。RDP 再核对 Windows 版本、远程桌面开关、用户权限、3389 规则；不要通过关闭整个防火墙排错。

隧道建立了，但客户端仍访问不到 AI

先验证主机本地接口，再检查隧道窗口是否还在。客户端用 11435，主机服务用 11434；若客户端 11435 也被占用，只改 -L 第一个端口并同步调整客户端地址。出现 administratively prohibited 时，检查主机 SSH 的 AllowTcpForwarding / PermitOpen 配置和匹配规则。

重启、外出与断网前后要注意什么？

ZeroTier 与 sshd 设为自动启动并验证。Windows 托盘版 Ollama 通常依赖用户登录启动，不能把它当作已配置的开机系统服务；无人值守可评估任务计划或 Linux 服务。关闭自动睡眠并兼顾散热，重启后实测外部连接。安装、更新、下载需要联网；本地权重推理可离线，但 ZeroTier 远程连接通常仍需网络。

将来换 Linux 主机，哪些地方需要变化？

模型选择与客户端命令可复用；安装方式改按 Ollama Linux 文档，环境变量通过 systemd 配置，SSH 服务与防火墙按发行版设置。不要把 Windows 的 Set-Service 或 NetFirewall 命令直接复制过去。Windows RDP 主机流程也不适用于 Linux 桌面。
